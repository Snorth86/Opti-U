# Public and private boundaries

This repository is designed to show the shape of the competence without publishing the mechanisms that create differentiation.

## Public

- the category thesis;
- high-level system context and authority boundaries;
- definitions of evidence and validation stages;
- generic governance principles;
- aggregated, revision-bound validation results;
- synthetic clean-room reference implementations;
- explicit limitations and future validation objectives.

## Private

- production source code;
- internal contracts and complete event taxonomies;
- intervention ontology and behavioural sequencing;
- operational thresholds and promotion logic;
- safety-policy implementation and influence controls;
- deployment topology and infrastructure identifiers;
- model artefacts, internal prompts and evaluation corpora;
- real user or wearable data;
- vulnerability findings and operational security detail;
- non-public evidence mappings and raw diligence artefacts.

## Clean-room rule

Public reference code is written independently from generic principles. It uses synthetic data, generic names and deliberately invented constants. It does not copy production modules, schemas, fixtures, tests or thresholds.

## Diligence

More detailed technical evidence can be made available to appropriate counterparties under NDA. Public absence is not evidence absence; it is part of the IP and security boundary.
